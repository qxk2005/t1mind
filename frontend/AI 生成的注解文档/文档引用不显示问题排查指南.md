# 文档引用不显示问题排查指南

## 问题描述

用户选择文档后提问，AI能使用文档内容回答（RAG功能正常），但界面上没有显示文档引用列表。

## 排查步骤

### 步骤1：启用调试日志

我已经在代码中添加了详细的调试日志，现在你可以：

1. **重启应用**（确保新代码生效）

2. **选择文档并提问**

3. **查看控制台日志**，寻找以下标记：

```
📊 [METADATA] Parsing metadata: {...}  // 收到的原始metadata
📄 [DOC_RETRIEVAL] Found document reference: id=xxx, source=xxx  // 识别到文档引用
📊 [METADATA] Parsed X sources: ...  // 解析结果
```

### 步骤2：检查日志输出

#### 情况A：没有任何 `[METADATA]` 日志

**原因**：后端没有发送metadata

**解决方案**：
1. 检查后端RAG配置
2. 确认文档已正确索引
3. 查看后端日志中的 `[RAG]` 标记

#### 情况B：有 `[METADATA]` 但没有 `SOURCE_ID`

**示例日志**：
```
📊 [METADATA] Parsing metadata: {"step": "retrieving"}
```

**原因**：后端发送了metadata，但不包含文档引用

**可能原因**：
- RAG功能未正确检索到文档
- 后端没有在stream结束后发送sources
- 文档检索结果为空

**排查**：查看后端日志中的：
```rust
[RAG] 📚 检查文档检索: rag_ids=...
[RAG] 📖 文档检索完成: 找到 X 个相关文档
[VectorStore] Found X results
```

#### 情况C：有 `SOURCE_ID` 但没有解析成功

**示例日志**：
```
📊 [METADATA] Parsing metadata: {"SOURCE_ID": "uuid", "SOURCE": "appflowy"}
📊 [METADATA] Parsed 0 sources:
```

**原因**：metadata格式不匹配或解析失败

**解决方案**：检查metadata格式是否正确

#### 情况D：解析成功但UI不显示

**示例日志**：
```
📄 [DOC_RETRIEVAL] Found document reference: id=abc-123, source=appflowy
📊 [METADATA] Parsed 1 sources: appflowy:Loading...
```

**原因**：前端显示逻辑问题

**排查**：
1. 检查 `ai_text_message.dart` 中的条件判断
2. 确认 `_hasDocumentSources` 返回true
3. 检查 `AIMessageMetadata` 组件是否正常渲染

### 步骤3：检查后端日志

查找关键日志标记：

#### 文档检索相关

```rust
// rust-lib/flowy-ai/src/local_ai/chat/chains/conversation_chain.rs

[RAG] 📚 检查文档检索: question='...', rag_ids=[...], is_empty=false
[RAG] 📖 文档检索完成: 找到 X 个相关文档
```

如果看到 `is_empty=true` 或 `找到 0 个相关文档`，说明：
- 文档未被选中
- 向量索引未创建
- 查询未匹配到相关内容

#### 发送metadata相关

```rust
// conversation_chain.rs 第440-447行

// Stream source metadata after content
for source in sources {
    yield Ok(StreamData::new(
        json!(source),
        None,
        String::new(),
    ));
}
```

### 步骤4：验证数据流

完整的数据流应该是：

```
1. 用户选择文档
   └─> rag_ids 保存到数据库

2. 用户提问
   └─> 后端读取 rag_ids
   └─> 向量检索找到相关文档
   └─> 使用文档内容生成回答
   └─> 流结束后发送 sources metadata

3. 前端接收
   └─> AnswerStream 接收 metadata 事件
   └─> parseMetadata 解析 SOURCE_ID
   └─> 创建 ChatMessageRefSource
   └─> AIMessageMetadata 组件显示
```

### 步骤5：常见问题检查清单

- [ ] **文档已索引** - 在向量索引设置中确认文档状态
- [ ] **选择了文档** - 聊天输入框上方应显示选中的文档
- [ ] **RAG功能启用** - AI回答确实使用了文档内容
- [ ] **后端发送metadata** - 控制台有 `[METADATA]` 日志
- [ ] **包含SOURCE_ID** - metadata中有文档UUID
- [ ] **前端解析成功** - 日志显示 "Parsed X sources"
- [ ] **UI渲染正常** - `_hasDocumentSources` 返回true

## 已知问题和解决方案

### 问题1：文档未索引

**症状**：后端日志显示 `找到 0 个相关文档`

**解决**：
1. 进入设置 → AI → 向量索引
2. 确认文档状态为"已索引"
3. 如果未索引，点击"重新索引"

### 问题2：rag_ids未保存

**症状**：后端日志显示 `rag_ids=[], is_empty=true`

**解决**：
1. 重新选择文档
2. 检查数据库中的 `af_chat_table` 表
3. 确认 `rag_ids` 字段不为空

### 问题3：OpenAI兼容模式未启用RAG

**症状**：使用OpenAI/云端AI时没有文档引用

**说明**：当前实现中，OpenAI兼容模式会：
- 将文档内容添加到prompt中
- 但**不发送**sources metadata

**解决方案**（需要后端修改）：

在 `rust-lib/flowy-ai/src/middleware/chat_service_mw.rs` 的 `get_message_content_with_rag` 函数中，需要额外返回检索到的文档信息，并在stream结束后发送。

当前代码只返回了增强的消息内容，没有保存document信息：

```rust
// 需要修改的位置：第127-153行
```

## 总结

根据日志输出，你可以快速定位问题：

| 日志输出 | 问题位置 | 解决方向 |
|---------|---------|---------|
| 无任何metadata日志 | 后端未发送 | 检查RAG功能、文档索引 |
| 有metadata但无SOURCE_ID | 后端格式问题 | 检查deduplicate_metadata函数 |
| 有SOURCE_ID但解析失败 | 前端解析问题 | 检查parseMetadata逻辑 |
| 解析成功但不显示 | UI渲染问题 | 检查_hasDocumentSources和组件 |
