# 文档引用真实名称显示和新标签页打开功能

## 功能概述

增强文档检索引用显示功能：
1. ✅ **显示真实文档名称** - 不再显示"document"等占位符，而是显示实际的文档名
2. ✅ **新标签页打开** - 点击文档引用时在新标签页打开文档进行编辑

## 实现细节

### 1. 真实文档名称显示

#### 数据流程

```
后端发送metadata:
{
  "SOURCE_ID": "document-uuid",
  "SOURCE": "appflowy"
}
        ↓
前端解析 (chat_message_service.dart):
ChatMessageRefSource(
  id: "document-uuid",
  name: "Loading...",    // 临时占位符
  source: "appflowy"
)
        ↓
AIMessageMetadata组件 (ai_metadata.dart):
1. 检测到UUID格式的id
2. 使用ViewBackendService.getView(id)异步查询
3. 加载成功后显示 state.view.nameOrDefault
4. 加载失败时fallback显示 m.name ("Loading...")
```

#### 关键代码

**前端解析** (`chat_message_service.dart`):

```dart
else if (map.containsKey("SOURCE_ID") && map["SOURCE_ID"] != null) {
  final sourceId = map["SOURCE_ID"].toString();
  final source = map["SOURCE"]?.toString() ?? "appflowy";
  
  Log.info("📄 [DOC_RETRIEVAL] Found document reference: id=$sourceId, source=$source");
  
  metadata.add(ChatMessageRefSource(
    id: sourceId,
    name: "Loading...", // 临时占位符，加载时显示
    source: source,
  ));
}
```

**组件异步加载** (`ai_metadata.dart` 82-108行):

```dart
else if (isUUID(m.id)) {
  return FutureBuilder<ViewPB?>(
    future: ViewBackendService.getView(m.id).then((f) => f.toNullable()),
    builder: (context, snapshot) {
      final data = snapshot.data;
      if (!snapshot.hasData ||
          snapshot.connectionState != ConnectionState.done ||
          data == null) {
        // 加载中或失败：显示临时占位符
        return _MetadataButton(
          name: m.name,  // "Loading..."
          onTap: () => widget.onSelectedMetadata?.call(m),
        );
      }
      // 加载成功：显示真实文档名
      return BlocProvider(
        create: (_) => ViewBloc(view: data),
        child: BlocBuilder<ViewBloc, ViewState>(
          builder: (context, state) {
            return _MetadataButton(
              name: state.view.nameOrDefault,  // 真实文档名 ✅
              onTap: () => widget.onSelectedMetadata?.call(m),
            );
          },
        ),
      );
    },
  );
}
```

### 2. 新标签页打开文档

#### 新增函数

在 `message_util.dart` 中新增函数 `openDocumentReferenceInNewTab`:

```dart
/// Opens a document reference in a new tab (desktop) or push the page (mobile)
/// This is specifically for document references from chat citations
void openDocumentReferenceInNewTab(BuildContext context, ViewPB? view) {
  if (view == null) {
    showToastNotification(
      message: LocaleKeys.chat_openPagePreviewFailedToast.tr(),
      type: ToastificationType.error,
    );
    return;
  }
  if (UniversalPlatform.isDesktop) {
    // 在新标签页打开文档
    getIt<TabsBloc>().add(
      TabsEvent.openPlugin(
        plugin: view.plugin(),
      ),
    );
  } else {
    context.pushView(view);
  }
}
```

#### 关键区别

| 函数 | 事件 | 桌面端行为 | 用途 |
|------|------|------------|------|
| `openPageFromMessage` | `TabsEvent.openSecondaryPlugin` | 右侧边栏打开 | 保存消息到页面后预览 |
| `openDocumentReferenceInNewTab` | `TabsEvent.openPlugin` | **新标签页打开** | **文档引用点击** |

#### 使用

在 `text_message_widget.dart` 中使用新函数：

```dart
void _onSelectMetadata(
  BuildContext context,
  ChatMessageRefSource metadata,
) async {
  if (metadata.source == "appflowy") {
    final documentView =
        await ViewBackendService.getView(metadata.id).toNullable();
    if (context.mounted) {
      // ✨ 在新标签页打开文档进行编辑
      openDocumentReferenceInNewTab(context, documentView);
    }
    return;
  }
  // ... 其他source处理
}
```

## 技术优势

### 1. 异步加载设计

- ✅ **非阻塞**: 不阻塞消息显示，先显示占位符
- ✅ **自动更新**: FutureBuilder自动在数据加载后更新UI
- ✅ **容错处理**: 加载失败时优雅降级

### 2. 职责分离

- **chat_message_service.dart**: 只负责识别SOURCE_ID格式
- **AIMessageMetadata组件**: 负责异步加载和显示真实名称
- **message_util.dart**: 负责统一的页面导航逻辑

### 3. 用户体验

- ✅ **清晰标识**: 用户能看到AI引用了哪个具体文档
- ✅ **快速访问**: 点击即可在新标签页打开编辑
- ✅ **工作流优化**: 不干扰当前聊天，可以并行编辑文档

## 常见问题

### Q: 为什么不直接在metadata中包含文档名？

A: 有几个原因：
1. **数据一致性**: 文档名可能变化，从源头查询确保最新
2. **权限检查**: getView会检查用户是否有权限访问
3. **架构清晰**: 保持后端只负责ID，前端负责展示

### Q: 加载很慢怎么办？

A: 当前设计已考虑：
- 显示"Loading..."占位符不阻塞UI
- FutureBuilder只加载一次，结果会缓存
- 可以考虑添加全局文档名称缓存

### Q: 为什么要在新标签页打开？

A: 用户体验考虑：
- 保持聊天上下文不被中断
- 可以并行查看文档和继续对话
- 符合现代应用的多标签工作流

### Q: 能否在侧边栏打开？

A: 可以，只需使用原来的`openPageFromMessage`函数。当前设计保留了两个函数，可以根据需要选择。
