# 多路召回系统集成完成

## 概述

成功实现了一个完整的**多路召回系统**（Multi-Retrieval System），让智能体能够：

1. **任务分解**：将复杂用户问题自动分解为多个子任务
2. **并行执行**：同时调用多个工具（文档RAG、Web Search、MCP工具等）
3. **结果综合**：使用AI将所有结果综合成连贯的最终答案

## 详细设计

### 1. TaskDecomposer - 任务分解器

**职责**：使用全局AI模型的能力将用户问题分解为子任务

**关键特性**：
- 智能判断问题是否需要分解
- 为每个子任务推荐最合适的工具
- 设置优先级和并行性标记

**数据结构**：

```rust
pub struct SubTask {
    pub id: String,
    pub description: String,
    pub recommended_tool: ToolType,
    pub priority: u8,
    pub can_parallel: bool,
}

pub enum ToolType {
    DocumentRag,
    WebSearch,
    Mcp { server_id: String, tool_name: String },
    Native { tool_name: String },
    None,
}
```

**示例分解**：

```
用户问题: "对比我们的内部定价策略和当前市场趋势"

分解结果:
├─ SubTask 1 (priority: 5, parallel: true)
│  ├─ description: "检索内部定价策略文档"
│  └─ tool: DocumentRag
│
├─ SubTask 2 (priority: 4, parallel: true)
│  ├─ description: "搜索当前市场定价趋势"
│  └─ tool: WebSearch
│
└─ 综合任务: 对比两个来源的信息
```

### 2. ParallelDispatcher - 并行调度器

**职责**：并行执行所有子任务，收集结果

**关键特性**：
- 使用 `tokio::join_all` 实现真正的并行
- 支持串行任务（如果需要）
- 详细的执行统计和错误处理

**执行流程**：

```rust
// 并行执行可并行任务
let futures: Vec<_> = parallel_tasks
    .into_iter()
    .map(|task| async move {
        execute_single_task(task, ...).await
    })
    .collect();

let results = join_all(futures).await;

// 串行执行需要串行的任务
for task in serial_tasks {
    let result = execute_single_task(task, ...).await;
    results.push(result);
}
```

**执行结果**：

```rust
pub struct SubTaskResult {
    pub task_id: String,
    pub success: bool,
    pub content: String,
    pub duration_ms: u64,
    pub source: String,
}

pub struct DispatchResult {
    pub results: Vec<SubTaskResult>,
    pub success_count: usize,
    pub failure_count: usize,
    pub total_duration_ms: u64,
}
```

### 3. ResultSynthesizer - 结果综合器

**职责**：使用AI将多个工具结果综合成最终答案

**关键特性**：
- 支持流式输出（实时显示）
- 自动引用来源
- 处理信息冲突
- 标注缺失信息

**综合提示词结构**：

```

综合多个信息源回答用户问题

```

## 集成到 Chat Service

### 主入口方法

在 `ChatServiceMiddleware` 中添加了新方法：

```rust
pub async fn stream_answer_with_multi_retrieval(
    &self,
    workspace_id: &Uuid,
    chat_id: &Uuid,
    question_id: i64,
    format: ResponseFormat,
    ai_model: AIModel,
    system_prompt: Option<String>,
    tool_handler: Arc<ToolCallHandler>,
    agent_config: Option<Arc<AgentConfigPB>>,
    available_tools: AvailableTools,
) -> Result<StreamAnswer, FlowyError>
```

### 执行流程

```rust
// 1. 任务分解
let decomposer = TaskDecomposer::new(...);
let decomposition = decomposer.decompose(&question, &available_tools, None).await?;

// 2. 并行执行
let dispatcher = ParallelDispatcher::new(tool_handler)
    .with_rag_context(chat_id, workspace_id);
let dispatch_result = dispatcher.dispatch_parallel(decomposition.sub_tasks, ...).await?;

// 3. 结果综合（流式）
let synthesizer = ResultSynthesizer::new(...);
let synthesis_stream = synthesizer.synthesize_stream(&question, &dispatch_result, ...).await?;

// 4. 返回流式响应
```

### 流式输出格式

系统通过 `QuestionStreamValue` 发送多种类型的消息：

1. **Metadata** - 进度和状态信息
   ```json
   {
     "multi_retrieval": {
       "phase": "decomposition",
       "sub_tasks_count": 2,
       "reasoning": "..."
     }
   }
   ```

2. **Sub-Task Results** - 每个子任务的执行结果
   ```json
   {
     "sub_task_result": {
       "task_id": "task_1",
       "tool_used": "DocumentRag",
       "success": true,
       "duration_ms": 150
     }
   }
   ```

3. **Answer** - 实际答案内容（流式）
   ```
   根据内部文档，我们的定价策略...
   而市场趋势显示...
   综合两方面信息...
   ```

## 使用示例

### 基本使用

```rust
use crate::agent::{AvailableTools, MCPToolInfo};

// 构建可用工具列表
let mut available_tools = AvailableTools::default();
available_tools.has_document_rag = true;
available_tools.has_web_search = true;

// 添加 MCP 工具
let mut mcp_tools = HashMap::new();
mcp_tools.insert(
    "excel_server".to_string(),
    vec![MCPToolInfo {
        name: "read_excel".to_string(),
        description: Some("Read Excel file".to_string()),
    }]
);
available_tools.mcp_tools = mcp_tools;

// 调用多路召回
let stream = chat_service.stream_answer_with_multi_retrieval(
    &workspace_id,
    &chat_id,
    question_id,
    format,
    ai_model,
    Some(system_prompt),
    tool_handler,
    agent_config,
    available_tools,
).await?;
```

### 自动检测使用

系统会自动判断问题是否需要多路召回：

- **简单问题**：自动fallback到单工具流程
  ```
  "文档X的内容是什么？" → 仅使用 DocumentRag
  ```

- **复杂问题**：启用多路召回
  ```
  "对比内部策略和市场趋势" → DocumentRag + WebSearch
  ```

## 性能优化

### 1. 真正的并行执行

使用 `tokio::join_all` 而不是顺序执行：

```rust
// ✅ 并行 - 所有任务同时开始
let futures = tasks.into_iter().map(|t| execute(t)).collect();
let results = join_all(futures).await;

// ❌ 串行 - 任务一个接一个
for task in tasks {
    results.push(execute(task).await);
}
```

### 2. 流式输出

结果综合使用流式API，用户可以实时看到答案生成：

```rust
let synthesis_stream = synthesizer.synthesize_stream(...).await?;

while let Some(chunk) = synthesis_stream.next().await {
    yield QuestionStreamValue::Answer { value: chunk };
}
```

### 3. 智能缓存

- 任务分解结果可以缓存
- RAG文档检索结果可以重用
- Web搜索结果有时效性控制

## 错误处理

### 1. 部分失败处理

即使某些子任务失败，系统仍能继续：

```rust
// 统计结果
let success_count = results.iter().filter(|r| r.success).count();

// 即使只有部分成功，仍尝试综合
if success_count > 0 {
    synthesizer.synthesize(...).await
}
```

### 2. 降级策略

```rust
// 如果任务分解失败或不需要分解
if !decomposition.needs_decomposition {
    // 降级到原有的单工具流程
    return self.stream_answer_with_auto_multi_turn(...).await;
}
```

### 3. 超时保护

每个子任务都有执行时间记录，可以设置超时：

```rust
let start_time = Instant::now();
let result = execute_tool(...).await;
let duration_ms = start_time.elapsed().as_millis() as u64;
```

## 配置选项

可以通过智能体配置控制多路召回行为：

```rust
pub struct MultiRetrievalConfig {
    /// 是否启用多路召回
    pub enabled: bool,
    
    /// 最大并行任务数
    pub max_parallel_tasks: usize,
    
    /// 单个任务超时（秒）
    pub task_timeout_secs: u64,
    
    /// 最少成功任务数（少于此数则失败）
    pub min_success_count: usize,
    
    /// 是否在简单问题时自动降级
    pub auto_fallback: bool,
}
```
