# 多路召回引用调试日志使用指南

## 概述

我已经在代码中添加了详细的调试日志，帮助追踪引用在整个流程中的变化。现在请重新编译运行应用，测试相同的问题，并查看日志输出。

## 关键日志标记

### 1. 📊 [METADATA] - Metadata 解析

**位置**：`chat_message_service.dart` 的 `parseMetadata` 函数

**输出内容**：
```
📊 [METADATA] Parsing metadata: {...}
📊 [METADATA] Parsed 10 sources total:
  - Web search: 9 (title1, title2, ...)
  - MCP tools: 1 (mcp:unknown:web_baidu_search)
  - Documents: 0
```

**作用**：查看每次收到 metadata 时，解析出了哪些类型的引用。

**关键检查**：
- MCP 工具的引用是否被正确创建？
- `source` 字段是否是 `mcp:xxx` 格式？

### 2. 🔄 [SOURCES] - 引用合并过程

**位置**：`chat_ai_message_bloc.dart` 的 `_ReceiveMetadata` 事件处理器

**输出内容**：
```
🔄 [SOURCES] Merging sources...
🔄 [SOURCES] Current state sources: 9
🔄 [SOURCES]   Existing: web:title1
🔄 [SOURCES]   Existing: web:title2
🔄 [SOURCES] New metadata sources: 1
🔄 [SOURCES]   New: mcp:unknown:web_baidu_search
📊 [SOURCES] ✅ After merge: 10 sources
📊 [SOURCES]   - Web: 9, MCP: 1
```

**作用**：查看每次 metadata 更新时，sources 是如何累积的。

**关键检查**：
- 新的 sources 是否正确添加到现有的 sources 中？
- 合并后的总数是否正确？
- Web 和 MCP 的数量是否符合预期？

### 3. 💾 [SOURCES-MGR] - 全局管理器操作

**位置**：`sources_manager.dart` 的 `setSources` 和 `getSources` 方法

**输出内容**：
```
💾 [SOURCES] Saving to global manager: chatId=xxx, questionId=123
💾 [SOURCES-MGR] Saved 10 sources for chatId:123:
💾 [SOURCES-MGR]   - Web: 9, MCP: 1, Doc: 0
💾 [SOURCES-MGR]   - web:title1
💾 [SOURCES-MGR]   - web:title2
💾 [SOURCES-MGR]   - mcp:unknown:web_baidu_search
```

**作用**：查看 sources 是否成功保存到全局管理器。

**关键检查**：
- `questionId` 是否为 null？（如果为 null 则无法保存）
- 保存的 sources 是否包含所有类型？
- 保存时的分类统计是否正确？

### 4. 🏁 [STREAM] - 流结束

**位置**：`chat_ai_message_bloc.dart` 的 `onEnd` 回调

**输出内容**：
```
🏁 [STREAM] Stream ended, checking sources...
🏁 [STREAM] questionId: 123, sources count: 10
🏁 [STREAM] Final sources breakdown: Web=9, MCP=1
🏁 [STREAM]   - web:title1
🏁 [STREAM]   - mcp:unknown:web_baidu_search
💾 [STREAM] ✅ Stream ended, saved 10 sources to global manager
```

**作用**：查看流结束时的最终 sources 状态。

**关键检查**：
- 流结束时 sources 是否完整？
- 是否成功保存到全局管理器？

### 5. 📨 [MSG-HANDLER] - 创建最终消息

**位置**：`chat_message_handler.dart` 的 `createTextMessage` 方法

**输出内容**：
```
📨 [MSG-HANDLER] Creating message 12345, hasReplyMessageId: true
📨 [MSG-HANDLER] Backend metadata length: 500
💾 [MSG-HANDLER] Looking for sources with chatId=xxx, questionId=123
💾 [MSG-HANDLER] Found 10 sources in global manager
💾 [MSG-HANDLER]   - web:title1
💾 [MSG-HANDLER]   - mcp:unknown:web_baidu_search
💾 [MSG-HANDLER] ✅ Restored 10 sources from global manager
💾 [MSG-HANDLER] Final metadata length: 2000
```

**作用**：查看创建最终消息时，是否从全局管理器恢复了完整的 sources。

**关键检查**：
- 是否找到了全局 sources？
- 恢复的 sources 是否完整？
- 如果没找到，是 chatId/questionId 不匹配，还是根本没保存？

### 6. 🌐/🔧 [UI] - UI 显示检查

**位置**：`ai_text_message.dart` 的 `_hasWebSearchCitations` 和 `_hasMCPReferences` 方法

**输出内容**：
```
🌐 [UI] Has web search citations: 9
🔧 [UI] Has MCP references: 1 - mcp:unknown:web_baidu_search
```

或者：
```
🔧 [UI] No MCP references found. All sources: web:title1, web:title2, ...
```

**作用**：查看 UI 显示时的 sources 状态。

**关键检查**：
- UI 收到的 sources 是否完整？
- 如果不完整，是哪个环节丢失的？

## 完整的调试流程

### 步骤 1：测试问题

1. 重新编译运行应用
2. 询问同样的问题（触发多个工具调用）
3. 等待回答完成

### 步骤 2：收集日志

按照顺序查找以下日志：

```
1️⃣ 流式传输过程
   ├─ 📊 [METADATA] - 第一次 metadata（web_search）
   ├─ 🔄 [SOURCES] - 合并 sources
   ├─ 💾 [SOURCES-MGR] - 保存到全局管理器
   │
   ├─ 📊 [METADATA] - 第二次 metadata（web_baidu_search）
   ├─ 🔄 [SOURCES] - 再次合并 sources
   └─ 💾 [SOURCES-MGR] - 再次保存到全局管理器

2️⃣ 流结束
   └─ 🏁 [STREAM] - 检查最终 sources

3️⃣ 创建最终消息
   └─ 📨 [MSG-HANDLER] - 从全局管理器恢复 sources

4️⃣ UI 显示
   ├─ 🌐 [UI] - 检查网络搜索引用
   └─ 🔧 [UI] - 检查 MCP 工具引用
```

### 步骤 3：分析问题

根据日志找出问题环节：

#### 场景 A：MCP 引用没有被创建

**日志表现**：
```
📊 [METADATA] Parsed 1 sources total:
  - Web search: 0
  - MCP tools: 0  ❌ 应该是 1
  - Documents: 0
```

**原因**：后端没有发送 MCP 工具的 metadata，或者 metadata 格式不对。

**排查方向**：检查后端代码，确保发送了 tool_call metadata。

#### 场景 B：引用在合并时丢失

**日志表现**：
```
🔄 [SOURCES] Current state sources: 9
🔄 [SOURCES] New metadata sources: 1
📊 [SOURCES] ✅ After merge: 9  ❌ 应该是 10
```

**原因**：`_mergeSources` 方法有 bug，去重逻辑错误。

**排查方向**：检查 `_mergeSources` 的实现。

#### 场景 C：保存到全局管理器失败

**日志表现**：
```
⚠️ [SOURCES] questionId is null, cannot save to global manager!
```

**原因**：`questionId` 为 null，无法生成唯一键。

**排查方向**：检查为什么 questionId 为 null。

#### 场景 D：从全局管理器恢复失败

**日志表现**：
```
💾 [MSG-HANDLER] Found 0 sources in global manager
⚠️ [MSG-HANDLER] No global sources found, using backend metadata
```

**原因**：chatId 或 questionId 不匹配，或者保存时用的是不同的 ID。

**排查方向**：对比保存和恢复时的 chatId/questionId 是否一致。

#### 场景 E：UI 收到的 sources 不完整

**日志表现**：
```
🔧 [UI] No MCP references found. All sources: web:title1, web:title2, ...
```

**原因**：虽然保存和恢复都成功，但传递到 UI 的 sources 不完整。

**排查方向**：检查 Widget 的状态传递逻辑。
