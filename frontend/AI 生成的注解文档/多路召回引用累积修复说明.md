# 多路召回引用累积修复说明

## 问题描述

在 AI 聊天中，当用户的问题触发多个工具（例如：网络搜索、MCP工具等）时，最终显示的引用列表中只包含**最后一个工具**的结果，之前工具的引用被覆盖丢失。

### 问题表现

- 用户询问"品高股份周边的房价如何？"
- AI 调用了多个工具：
  - `web_search`（网络搜索）
  - `web_baidu_search`（百度搜索）
  - 其他可能的 MCP 工具
- 但最终引用列表中**只显示了网络搜索的引用**（9个），其他工具的引用不见了

## 根本原因

### 代码层面

在 `chat_ai_message_bloc.dart` 的 `_ReceiveMetadata` 事件处理器中：

```dart
emit(
  state.copyWith(
    sources: event.metadata.sources,  // ❌ 问题：直接替换，不是累积
    progress: event.metadata.progress,
    ...
  ),
);
```

### 流程分析

1. **多路召回系统架构**：
   - Rust 后端的多路召回系统会分别调用不同的工具
   - 每个工具的结果通过**独立的 metadata 事件**发送到前端
   
2. **Metadata 发送顺序**（示例）：
   ```
   Metadata Event 1: { sources: [web_search引用1, web_search引用2, ...] }
   Metadata Event 2: { sources: [mcp工具引用1, mcp工具引用2, ...] }
   Metadata Event 3: { sources: [百度搜索引用1, 百度搜索引用2, ...] }
   ```

3. **前端处理问题**：
   - 每次接收到新的 metadata 事件时
   - 直接用 `event.metadata.sources` **替换**整个 sources 列表
   - 导致之前工具的引用被**覆盖丢失**

## 解决方案

### 核心思路

将 `sources` 的处理从**替换模式**改为**累积模式**：
- ✅ 将新的 sources 合并到现有的 sources 中
- ✅ 使用去重逻辑避免重复引用
- ✅ 保留所有工具的引用结果

### 实现细节

#### 1. 修改 `_ReceiveMetadata` 事件处理器

```dart
// 🔧 累积引用来源（修复多路召回时只显示一种工具结果的问题）
// 将新的 sources 与现有的 sources 合并，而不是直接替换
List<ChatMessageRefSource> updatedSources = _mergeSources(state.sources, event.metadata.sources);

Log.info("📊 [SOURCES] Updated sources count: ${updatedSources.length} (previous: ${state.sources.length}, new: ${event.metadata.sources.length})");

emit(
  state.copyWith(
    sources: updatedSources,  // ✅ 使用合并后的 sources
    progress: event.metadata.progress,
    ...
  ),
);
```

#### 2. 新增 `_mergeSources` 方法

```dart
/// 🔧 合并引用来源列表（修复多路召回时只显示一种工具结果的问题）
/// 
/// 该方法将新的 sources 累积到现有的 sources 中，而不是替换它们。
/// 使用唯一标识（source + id）进行去重，避免重复添加相同的引用。
List<ChatMessageRefSource> _mergeSources(
  List<ChatMessageRefSource> existingSources,
  List<ChatMessageRefSource> newSources,
) {
  if (newSources.isEmpty) {
    return existingSources;
  }

  // 创建一个副本，避免修改原列表
  final List<ChatMessageRefSource> mergedSources = List.from(existingSources);
  
  // 为了去重，使用 source + id 作为唯一标识
  final Set<String> existingKeys = existingSources
      .map((source) => '${source.source}:${source.id}')
      .toSet();
  
  // 添加新的 sources（跳过重复的）
  for (final newSource in newSources) {
    final key = '${newSource.source}:${newSource.id}';
    if (!existingKeys.contains(key)) {
      mergedSources.add(newSource);
      existingKeys.add(key);
      Log.debug("📊 [SOURCES] Added new source: ${newSource.source}:${newSource.name}");
    } else {
      Log.debug("📊 [SOURCES] Skipped duplicate source: ${newSource.source}:${newSource.name}");
    }
  }
  
  return mergedSources;
}
```

### 去重策略

使用 `source + id` 作为唯一标识：
- `web:https://example.com/article1` - 网络搜索引用
- `mcp:server_name:tool_name` - MCP 工具引用
- `appflowy:document_uuid` - 文档引用

这样可以确保：
- ✅ 来自不同工具的引用都能保留
- ✅ 同一个引用不会重复添加
- ✅ 引用列表按添加顺序排列

## 注意事项

1. **引用顺序**：引用按照接收顺序添加，不同工具的引用会交错出现
2. **去重逻辑**：如果同一个引用（相同的 source + id）多次出现，只保留第一次
3. **内存使用**：引用列表会累积增长，但通常不会超过几十个引用，内存影响可忽略

## 后续优化建议

1. **引用排序**：可以考虑按照引用类型或相关性对引用进行排序
2. **引用限制**：如果引用数量过多（如超过100个），可以考虑限制显示数量
3. **引用更新**：如果同一个引用有更新（如 RAG 文档的内容变化），需要考虑是否更新
