# 文档检索引用显示修复

## 问题描述

用户报告：在AI聊天中选择文档并提问时，虽然AI能够使用文档内容回答问题（RAG功能正常），但界面上没有显示文档引用信息，不像网络搜索那样显示引用来源。

## 问题原因

### 后端发送的数据格式

后端在进行RAG（Retrieval-Augmented Generation）文档检索后，会将检索到的文档作为metadata发送到前端。格式如下：

```json
{
  "SOURCE_ID": "document-uuid",
  "SOURCE": "appflowy",
  "SOURCE_NAME": "document"
}
```

**代码位置**: `rust-lib/flowy-ai/src/local_ai/chat/chains/conversation_chain.rs`

```rust
// 第416行：生成sources
let sources = deduplicate_metadata(&documents);

// 第440-447行：在stream结束后发送sources
for source in sources {
    yield Ok(StreamData::new(
        json!(source),
        None,
        String::new(),
    ));
}

// 第572-585行：deduplicate_metadata函数
fn deduplicate_metadata(documents: &[Document]) -> Vec<QuestionStreamValue> {
  let mut merged_metadata: HashMap<String, QuestionStreamValue> = HashMap::new();
  for document in documents {
    if let Some(object_id) = document.metadata.get(SOURCE_ID).and_then(|s| s.as_str()) {
      merged_metadata.insert(
        object_id.to_string(),
        QuestionStreamValue::Metadata {
          value: json!(document.metadata.clone()),
        },
      );
    }
  }
  merged_metadata.into_values().collect()
}
```

**文档索引时添加metadata**: `rust-lib/flowy-ai/src/embeddings/document_indexer.rs`

```rust
// 第103-105行
SOURCE_ID: object_id,
SOURCE: "appflowy",
SOURCE_NAME: "document",
```

### 前端解析问题

前端的`parseMetadata`函数只处理以下格式的metadata：

1. **包含`id`字段** - 标准的ChatMessageRefSource格式
2. **包含`step`字段** - 进度信息
3. **包含`reasoning_delta`字段** - 推理过程
4. **包含`tool_call`字段** - 工具调用（网络搜索、MCP工具等）

**但是不处理`SOURCE_ID`格式**，导致文档引用被忽略！

## 解决方案

### 修改内容

在`chat_message_service.dart`的`parseMetadata`函数中添加对`SOURCE_ID`格式的处理：

```dart
else if (map.containsKey("SOURCE_ID") && map["SOURCE_ID"] != null) {
  // 处理文档检索引用（RAG）
  // 格式: { "SOURCE_ID": "uuid", "SOURCE": "appflowy", "SOURCE_NAME": "document" }
  final sourceId = map["SOURCE_ID"].toString();
  final source = map["SOURCE"]?.toString() ?? "appflowy";
  
  // name字段留空，让AIMessageMetadata组件通过ViewBackendService异步加载真实文档名称
  // 如果加载失败，组件会fallback到显示source id
  Log.info("📄 [DOC_RETRIEVAL] Found document reference: id=$sourceId, source=$source");
  
  metadata.add(ChatMessageRefSource(
    id: sourceId,
    name: "", // 空name，让组件异步加载
    source: source,
  ));
}
```

### 为什么name留空？

`AIMessageMetadata`组件已经有完善的逻辑来处理文档名称的异步加载：

```dart
// ai_metadata.dart: 82-108行
else if (isUUID(m.id)) {
  return FutureBuilder<ViewPB?>(
    future: ViewBackendService.getView(m.id)
        .then((f) => f.toNullable()),
    builder: (context, snapshot) {
      final data = snapshot.data;
      if (!snapshot.hasData ||
          snapshot.connectionState != ConnectionState.done ||
          data == null) {
        return _MetadataButton(
          name: m.name,  // 加载中或失败时使用m.name
          onTap: () => widget.onSelectedMetadata?.call(m),
        );
      }
      return BlocProvider(
        create: (_) => ViewBloc(view: data),
        child: BlocBuilder<ViewBloc, ViewState>(
          builder: (context, state) {
            return _MetadataButton(
              name: state.view.nameOrDefault,  // 成功时使用真实文档名
              onTap: () => widget.onSelectedMetadata?.call(m),
            );
          },
        ),
      );
    },
  );
}
```

这个逻辑会：
1. 使用UUID查询ViewBackendService获取文档信息
2. 成功后显示`state.view.nameOrDefault`（真实文档名称）
3. 加载中或失败时fallback到`m.name`或显示UUID

## 已知限制

### 1. 文档名称加载延迟

- 文档名称需要异步加载，初次显示可能有短暂延迟
- 网络较慢时可能暂时显示空白或UUID

### 2. 去重逻辑

- 后端的`deduplicate_metadata`会对同一文档的多个片段去重
- 只保留一个文档引用，即使AI使用了该文档的多个片段

### 3. 文档片段信息

- 目前不显示具体引用了文档的哪些片段
- 未来可考虑添加片段预览功能

## 总结

通过添加对`SOURCE_ID`格式的metadata解析，成功修复了文档检索引用不显示的问题。现在用户可以清楚地看到AI回答引用了哪些文档，提高了回答的透明度和可追溯性。
