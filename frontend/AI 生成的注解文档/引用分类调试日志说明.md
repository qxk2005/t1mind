# 引用分类调试日志说明

## 问题描述

在多路召回场景下，当同时调用 AppFlowy 网络搜索（`web_search`）和 MCP 工具（如 `web_baidu_search`）时：
- **预期**：`web_search` 的引用应该显示在"网络搜索引用"列表，`web_baidu_search` 的引用应该显示在"MCP 工具引用"列表
- **实际**：只显示了"网络搜索引用"列表，"MCP 工具引用"列表没有出现

## 引用分类逻辑

### 工具类型识别

在 `chat_message_service.dart` 中：

```dart
if (toolName == "web_search") {
  // AppFlowy 网络搜索供应商
  // 从 result 字符串中提取 URL 引用
  // source: 'web'
  final citations = _extractCitationsFromSearchResult(result);
  metadata.addAll(citations);
} else {
  // 其他都是 MCP 工具（包括 web_baidu_search）
  // 创建 MCP 引用
  // source: 'mcp:server_id'
  final mcpReference = ChatMessageRefSource(
    id: toolCallId ?? toolName,
    name: displayName,
    source: 'mcp:${serverId ?? "unknown"}',
  );
  metadata.add(mcpReference);
}
```

### 前端显示分类

在 `ai_text_message.dart` 中：

```dart
// 网络搜索引用：source == 'web' && isURL(source.id)
```

### 2. UI 显示检查日志

在 `ai_text_message.dart` 的 `_hasMCPReferences` 函数中：

```dart
bool _hasMCPReferences(List<ChatMessageRefSource> sources) {
  final hasMCP = sources.any((source) => source.source.startsWith('mcp'));
  if (hasMCP) {
    final mcpSources = sources.where((source) => source.source.startsWith('mcp')).toList();
    Log.info("🔧 [UI] Has MCP references: ${mcpSources.length} - ${mcpSources.map((s) => '${s.source}:${s.name}').join(', ')}");
  } else {
    final allSources = sources.map((s) => '${s.source}:${s.name}').join(', ');
    Log.info("🔧 [UI] No MCP references found. All sources: $allSources");
  }
  return hasMCP;
}
```

**作用**：
- 如果有 MCP 引用：输出 MCP 引用的详细信息
- 如果没有 MCP 引用：输出所有 sources 的信息，帮助排查为什么没有 MCP 引用

## 如何使用日志排查问题

### 场景1：MCP 工具引用没有被创建

**日志表现**：
```
📊 [METADATA] Parsed 10 sources total:
  - Web search: 10 (title1, title2, ...)
  - MCP tools: 0 ()
  - Documents: 0

🔧 [UI] No MCP references found. All sources: web:title1, web:title2, ...
```

**原因**：MCP 工具的 metadata 没有被正确解析，或者根本没有发送。

**排查方向**：
1. 检查后端是否发送了 MCP 工具的 metadata
2. 检查 metadata 的格式是否正确
3. 检查 `tool_call` 字段的解析逻辑

### 场景2：MCP 工具引用被创建但在累积过程中丢失

**日志表现**：
```
// 流式传输过程中
📊 [METADATA] Parsed 5 sources total:
  - Web search: 5 (...)
  - MCP tools: 0 ()

📊 [METADATA] Parsed 1 sources total:
  - Web search: 0 ()
  - MCP tools: 1 (mcp:unknown:web_baidu_search)

📊 [SOURCES] Updated sources count: 6 (previous: 5, new: 1)

// 但最终显示时
🔧 [UI] No MCP references found. All sources: web:title1, web:title2, ...
```

**原因**：引用在累积过程中正确添加，但在持久化或重新加载时丢失。

**排查方向**：
1. 检查 `SourcesManager` 是否正确保存了 MCP 引用
2. 检查消息重新加载时是否正确恢复了 MCP 引用
3. 检查是否有其他地方覆盖了 sources

### 场景3：MCP 工具引用的 source 格式不正确

**日志表现**：
```
📊 [METADATA] Parsed 11 sources total:
  - Web search: 10 (...)
  - MCP tools: 0 ()
  - Documents: 0

🔧 [UI] No MCP references found. All sources: web:title1, web:title2, ..., xxx:web_baidu_search
```

**原因**：MCP 工具引用的 `source` 字段格式不正确，不是以 `mcp` 开头。

**排查方向**：
1. 检查创建 MCP 引用时 `source` 字段的值
2. 确保使用 `'mcp:${serverId ?? "unknown"}'` 格式

## 可能的问题和解决方案

### 问题1：后端只发送了最后一次的 metadata

**表现**：只看到一个 `📊 [METADATA]` 日志，包含所有引用但都是同一类型。

**解决**：这是后端问题，需要确保每个工具调用都发送独立的 metadata。

### 问题2：前端累积逻辑有 bug

**表现**：看到多个 `📊 [METADATA]` 日志，但 `📊 [SOURCES]` 累积的总数不对。

**解决**：检查 `_mergeSources` 逻辑，确保正确去重和累积。

### 问题3：source 格式不正确

**表现**：MCP 工具引用被创建，但 `source` 不是以 `mcp` 开头。

**解决**：修改 MCP 引用创建逻辑，确保 `source` 格式正确。
