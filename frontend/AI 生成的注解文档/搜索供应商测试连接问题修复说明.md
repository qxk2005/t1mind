# 搜索供应商测试连接问题修复说明

## 问题描述

用户在添加搜索供应商后，点击"测试所有连接"按钮，界面一直显示"连接中"状态，测试无法完成。

## 错误日志

```
thread '<unnamed>' panicked at flowy-ai/src/web_search/provider_manager.rs:725:48:
Cannot start a runtime from within a runtime. This happens because a function (like `block_on`) attempted to block the current thread while the thread is being used to drive asynchronous tasks.
```

## 根本原因分析

这是一个典型的 Tokio 异步运行时嵌套错误：

### 调用链分析

1. **UI 层** → Flutter BLoC `testProvider` 事件
2. **BLoC 层** → `AIEventTestWebSearchProvider().send()` (异步)
3. **Event Handler** → `test_web_search_provider_handler()` (async)
4. **Hub 层** → `web_search_hub.test_provider()` (async)
5. **Manager 层** → `provider_manager.test_provider()` (同步 ❌)
6. **执行层** → `execute_provider_tests()` (同步 ❌)
   - 使用 `tokio::runtime::Handle::current()`
   - 调用 `rt.block_on(provider.run_tests())` ❌ **这里出错了！**

### 问题说明

在已有的异步运行时中使用 `block_on` 会导致运行时嵌套错误：

```rust
// ❌ 错误的做法
fn execute_provider_tests(&self, config: &WebSearchProviderConfigPB) -> FlowyResult<...> {
    let rt = tokio::runtime::Handle::current();
    let test_response = rt.block_on(provider.run_tests())?;  // 嵌套错误！
    // ...
}
```

当前代码在一个已经运行的异步上下文中尝试使用 `block_on` 阻塞当前线程，这会导致死锁和 panic。

## 解决方案

将同步方法改为异步方法，直接使用 `await` 而不是 `block_on`：

### 修改 1: `execute_provider_tests` 方法

**文件**: `rust-lib/flowy-ai/src/web_search/provider_manager.rs`

**修改前**:
```rust
fn execute_provider_tests(&self, config: &WebSearchProviderConfigPB) -> FlowyResult<Vec<WebSearchTestResultPB>> {
    match config.provider_type {
        WebSearchProviderTypePB::Tavily => {
            match crate::web_search::providers::create_tavily_provider(config.clone()) {
                Ok(provider) => {
                    // 使用异步运行时执行测试
                    let rt = tokio::runtime::Handle::current();
                    let test_response = rt.block_on(provider.run_tests())?;  // ❌ 错误
                    Ok(test_response.test_results)
                }
                Err(e) => Err(e),
            }
        }
        // ... 其他分支
    }
}
```

**修改后**:
```rust
async fn execute_provider_tests(&self, config: &WebSearchProviderConfigPB) -> FlowyResult<Vec<WebSearchTestResultPB>> {
    match config.provider_type {
        WebSearchProviderTypePB::Tavily => {
            match crate::web_search::providers::create_tavily_provider(config.clone()) {
                Ok(provider) => {
                    // 直接 await 异步测试 ✅
                    let test_response = provider.run_tests().await?;
                    Ok(test_response.test_results)
                }
                Err(e) => Err(e),
            }
        }
        WebSearchProviderTypePB::BraveSearch => {
            match crate::web_search::providers::create_brave_search_provider(config.clone()) {
                Ok(provider) => {
                    // 直接 await 异步测试 ✅
                    let test_response = provider.run_tests().await?;
                    Ok(test_response.test_results)
                }
                Err(e) => Err(e),
            }
        }
        WebSearchProviderTypePB::Custom => {
            // ... 自定义供应商逻辑
        }
    }
}
```

## 修复后的调用链

现在整个调用链都是异步的：

1. **UI 层** → Flutter BLoC `testProvider` 事件
2. **BLoC 层** → `AIEventTestWebSearchProvider().send()` (async)
3. **Event Handler** → `test_web_search_provider_handler()` (async)
4. **Hub 层** → `web_search_hub.test_provider().await` (async ✅)
5. **Manager 层** → `provider_manager.test_provider().await` (async ✅)
6. **执行层** → `execute_provider_tests().await` (async ✅)
   - 直接 `provider.run_tests().await` ✅ **正确！**

整个调用链现在都使用 `await` 而不是 `block_on`，不会出现运行时嵌套问题。

## 技术要点

### Tokio 异步运行时规则

1. **在异步上下文中，使用 `await` 而不是 `block_on`**
   - ✅ `let result = async_function().await;`
   - ❌ `let result = runtime.block_on(async_function());`

2. **`block_on` 只能在以下场景使用**:
   - 在 `main` 函数中启动异步运行时
   - 在完全同步的上下文中（没有活动的运行时）
   - 在测试中（但最好使用 `#[tokio::test]`）

3. **异步传染性**:
   - 如果一个函数需要调用异步函数，它自己也应该是异步的
   - 整个调用链应该保持异步一致性

### 错误模式识别

当看到以下错误时：
```
Cannot start a runtime from within a runtime
```

这意味着：
- 在已有的异步上下文中使用了 `block_on`
- 需要将同步方法改为异步方法
- 需要使用 `await` 而不是 `block_on`

## 总结

这次修复解决了异步运行时嵌套的关键问题。核心原则是：

1. **保持异步一致性**：整个调用链应该都是异步的
2. **使用 `await` 而不是 `block_on`**：在异步上下文中直接 await
3. **避免运行时嵌套**：不要在已有的运行时中创建或阻塞新的运行时

修复后，测试连接功能应该可以正常工作，不会再出现卡死或 panic 的情况。
