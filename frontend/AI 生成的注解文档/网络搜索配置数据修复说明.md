# 网络搜索配置数据修复说明

## 问题描述

在全局设置中添加网络搜索服务商时出现 Protocol Buffer 序列化错误：

```
[error] 加载网络搜索供应商列表异常: InvalidProtocolBufferException: Protocol message end-group tag did not match expected tag.
[error] 加载网络搜索全局配置异常: InvalidProtocolBufferException: Protocol message end-group tag did not match expected tag.
```

## 问题原因

这个错误是由于以下原因造成的：

1. **数据格式不匹配**：数据库中存储的旧配置数据格式与当前的 Protocol Buffer 定义不匹配
2. **反序列化失败**：当 KVStore 尝试从 JSON 反序列化旧数据到新的结构体时失败
3. **缺少错误处理**：代码在反序列化失败时没有自动清理损坏的数据

这通常发生在以下情况：
- Protocol Buffer 定义发生了更改（添加、删除或修改字段）
- 应用升级后，旧版本的配置数据无法正确加载

## 修复方案

### 1. 自动清理损坏数据（已实施）

修改了 `rust-lib/flowy-ai/src/web_search/provider_manager.rs` 中的以下函数：

#### `get_global_settings()` - 全局配置读取
```rust
/// 获取全局网络搜索设置
pub fn get_global_settings(&self) -> WebSearchGlobalConfigPB {
    match self.store_preferences.get_object::<WebSearchGlobalConfigPB>(WEB_SEARCH_GLOBAL_SETTINGS_KEY) {
        Some(config) => config,
        None => {
            warn!("Failed to load web search global settings, using default config");
            // 清理可能损坏的数据
            self.store_preferences.remove(WEB_SEARCH_GLOBAL_SETTINGS_KEY);
            let default_config = WebSearchGlobalConfigPB::default_config();
            // 保存默认配置
            if let Err(e) = self.save_global_settings(default_config.clone()) {
                error!("Failed to save default global settings: {}", e);
            }
            default_config
        }
    }
}
```

**改进内容**：
- 当反序列化失败时，自动清理损坏的全局配置数据
- 返回并保存默认配置，确保应用可以正常工作

#### `get_all_providers()` - 供应商列表读取
```rust
pub fn get_all_providers(&self) -> FlowyResult<WebSearchProviderListPB> {
    let provider_ids: Vec<String> = match self.store_preferences.get_object::<Vec<String>>(WEB_SEARCH_PROVIDER_LIST_KEY) {
        Some(ids) => ids,
        None => {
            warn!("Failed to load provider list, clearing and returning empty list");
            self.store_preferences.remove(WEB_SEARCH_PROVIDER_LIST_KEY);
            Vec::new()
        }
    };
    
    // ... 清理损坏的供应商配置
}
```

**改进内容**：
- 当供应商列表读取失败时，自动清理并返回空列表
- 自动检测并清理损坏的单个供应商配置

#### `get_provider_config()` - 单个供应商配置读取
```rust
fn get_provider_config(&self, provider_id: &str) -> Option<WebSearchProviderConfigPB> {
    let key = self.provider_config_key(provider_id);
    match self.store_preferences.get_object::<WebSearchProviderConfigPB>(&key) {
        Some(config) => Some(config),
        None => {
            // 如果反序列化失败，清理损坏的数据
            warn!("Failed to deserialize provider config for ID: {}, removing corrupted data", provider_id);
            self.store_preferences.remove(&key);
            None
        }
    }
}
```

**改进内容**：
- 当单个供应商配置反序列化失败时，自动清理该配置
- 防止损坏的配置影响其他正常配置

cd appflowy_flutter

### 2. 验证修复

1. **打开全局设置** → **网络搜索配置**
2. **检查界面**：

   - 不应该再看到 `InvalidProtocolBufferException` 错误
3. **添加新供应商**：
   - 点击"添加供应商"按钮
   - 填写供应商信息（名称、API Key、Base URL 等）
   - 点击保存
4. **验证功能**：
   - 供应商应该成功保存
   - 供应商列表应该正常显示
   - 可以正常激活/停用供应商

### 3. 查看日志

应用启动时，日志中应该会看到类似的清理消息（如果有损坏的数据）：

```
[warn] Failed to load web search global settings, using default config
[warn] Failed to load provider list, clearing and returning empty list
[warn] Failed to deserialize provider config for ID: xxx, removing corrupted data
[warn] Cleaning up N orphaned/corrupted provider IDs
```

这些警告是正常的，表示系统正在自动清理损坏的数据。

## 预防措施

为了防止将来出现类似问题，已经实施了以下措施：

1. **自动数据清理**：当反序列化失败时自动清理损坏的数据
2. **默认配置回退**：无法加载配置时使用默认配置
3. **孤立数据清理**：自动检测并清理孤立或损坏的配置项
4. **详细日志记录**：记录清理操作，便于调试

## 后续优化建议

1. **配置版本管理**：
   - 增强 `migrate_config_if_needed()` 函数
   - 在版本升级时主动迁移数据格式

2. **数据备份**：
   - 在清理损坏数据前备份到日志
   - 提供配置导出/导入功能

3. **用户通知**：
   - 当配置被重置时，通过 UI 通知用户
   - 提供手动重置配置的选项

## 总结

这次修复主要解决了 Protocol Buffer 反序列化失败导致的配置加载错误。通过添加自动清理机制，应用现在可以：

✅ 自动检测并清理损坏的配置数据  
✅ 在配置损坏时使用默认配置  
✅ 确保应用可以正常启动和运行  
✅ 提供详细的日志信息便于调试  

用户只需重新启动应用，系统会自动清理旧的损坏数据并恢复正常工作状态。
