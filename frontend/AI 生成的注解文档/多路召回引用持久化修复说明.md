# 多路召回引用持久化修复说明

## 问题描述

在 AI 聊天中，当调用多个工具（例如：网络搜索、MCP工具等）时：
- **流式传输过程中** ✅：可以看到多个分类的引用列表
- **回答完成后** ❌：只剩下一种工具的引用结果，其他引用消失

### 问题根本原因

这是在第一次修复（引用累积）之后暴露的第二个问题：

1. **流式传输过程中**：
   - `ChatAIMessageBloc` 正确累积了所有工具的引用
   - 前端可以看到完整的引用列表

2. **流结束时**：
   - 后端发送最终的 `ChatMessagePB` 消息
   - 该消息的 `metadata` 字段**只包含最后一次的 metadata**
   - 这个不完整的 metadata 被保存到数据库

3. **消息重新加载时**：
   - 从数据库读取时，`refSourceJsonString` 只包含最后一次的 metadata
   - 前端累积的所有 sources **丢失**

### 流程图

```
流式传输过程:
  Metadata 1 (web_search) → 累积 → 前端显示 [web_search]
  Metadata 2 (mcp_tool)   → 累积 → 前端显示 [web_search, mcp_tool]  ✅
  Metadata 3 (baidu)      → 累积 → 前端显示 [web_search, mcp_tool, baidu]  ✅

流结束:
  后端发送最终消息:
    ChatMessagePB.metadata = "只包含 Metadata 3"  ❌

消息重新加载:
  从数据库读取:
    refSourceJsonString = "只包含 Metadata 3"
    前端初始化: 只显示 [baidu]  ❌
```

## 解决方案

### 核心思路

创建一个全局管理器（类似 `ReasoningManager`）来持久化累积的 sources：
- 在流式传输过程中，将累积的 sources 保存到全局管理器
- 当消息被重新加载时，从全局管理器恢复累积的 sources

### 实现细节

#### 1. 创建 `SourcesManager`（新文件）

文件：`appflowy_flutter/lib/plugins/ai_chat/application/sources_manager.dart`

```dart
/// 全局管理器，用于累积和持久化聊天消息的引用来源（sources）
/// 
/// 使用 chatId + questionId 作为唯一标识来存储和检索 sources
class SourcesManager {
  // 单例模式
  static final SourcesManager _instance = SourcesManager._internal();
  factory SourcesManager() => _instance;
  SourcesManager._internal();

  // 使用 Map 存储每个消息的累积 sources
  // Key: "chatId:questionId"
  final Map<String, List<ChatMessageRefSource>> _sourcesMap = {};

  /// 获取指定消息的累积 sources
  List<ChatMessageRefSource>? getSources(String chatId, String questionId);

  /// 设置指定消息的 sources（完全替换）
  void setSources(String chatId, String questionId, List<ChatMessageRefSource> sources);

  /// 追加 sources 到指定消息（累积）
  void appendSources(String chatId, String questionId, List<ChatMessageRefSource> newSources);

  /// 清除指定消息的 sources
  void clearSources(String chatId, String questionId);

  /// 清除指定 chat 的所有 sources
  void clearChatSources(String chatId);
}
```

**特性**：
- ✅ 单例模式，全局唯一实例
- ✅ 使用 `chatId:questionId` 作为唯一键
- ✅ 支持去重（基于 `source:id`）
- ✅ 内存存储，性能高效

#### 2. 修改 `ChatAIMessageBloc`

文件：`appflowy_flutter/lib/plugins/ai_chat/application/chat_ai_message_bloc.dart`

##### 2.1 导入管理器

```dart
import 'package:appflowy/plugins/ai_chat/application/sources_manager.dart';
```

##### 2.2 添加管理器实例

```dart
final SourcesManager _sourcesManager = SourcesManager();
```

##### 2.3 初始化时从全局管理器加载 sources

```dart
/// 从全局管理器初始化引用来源
void _initializeSourcesFromGlobal() {
  if (questionId == null) return;
  
  final globalSources = _sourcesManager.getSources(chatId, questionId.toString());
  if (globalSources != null && globalSources.isNotEmpty) {
    Log.info("💾 [SOURCES] Initializing with ${globalSources.length} sources from global manager");
    add(ChatAIMessageEvent.initializeSources(globalSources));
  }
}
```

##### 2.4 接收 metadata 时保存到全局管理器

在 `_ReceiveMetadata` 事件处理器中：

```dart
// 🔧 累积引用来源
List<ChatMessageRefSource> updatedSources = _mergeSources(state.sources, event.metadata.sources);

// 💾 同时保存到全局管理器，确保消息重新加载时不丢失
if (questionId != null) {
  _sourcesManager.setSources(chatId, questionId.toString(), updatedSources);
  Log.debug("💾 [SOURCES-MGR] Saved ${updatedSources.length} sources to global manager");
}
```

##### 2.5 流结束时保存最终的 sources

在 `onEnd` 回调中：

```dart
// 💾 流结束时，确保累积的 sources 被保存到全局管理器
if (questionId != null && state.sources.isNotEmpty) {
  _sourcesManager.setSources(chatId, questionId.toString(), state.sources);
  Log.info("💾 [SOURCES-MGR] Stream ended, saved ${state.sources.length} sources to global manager");
}
```

##### 2.6 添加新事件

```dart
// 事件定义
const factory ChatAIMessageEvent.initializeSources(
  List<ChatMessageRefSource> sources,
) = _InitializeSources;

// 事件处理
on<_InitializeSources>((event, emit) {
  if (event.sources.isNotEmpty) {
    Log.info("💾 [SOURCES] Initializing with ${event.sources.length} sources from global manager");
    emit(
      state.copyWith(
        sources: event.sources,
      ),
    );
  }
});
```

## 工作流程

### 流式传输过程

```
1. 接收 Metadata 1 (web_search)
   ├─ 累积到 state.sources: [web_search]
   └─ 保存到全局管理器: setSources(chatId, questionId, [web_search])

2. 接收 Metadata 2 (mcp_tool)
   ├─ 累积到 state.sources: [web_search, mcp_tool]
   └─ 保存到全局管理器: setSources(chatId, questionId, [web_search, mcp_tool])

3. 接收 Metadata 3 (baidu)
   ├─ 累积到 state.sources: [web_search, mcp_tool, baidu]
   └─ 保存到全局管理器: setSources(chatId, questionId, [web_search, mcp_tool, baidu])

4. 流结束
   └─ 最终保存: setSources(chatId, questionId, [web_search, mcp_tool, baidu])
```

### 消息重新加载

```
1. 后端发送 ChatMessagePB
   └─ metadata = "只包含 Metadata 3" (不完整)

2. ChatAIMessageBloc 初始化
   ├─ parseMetadata(refSourceJsonString) → 只有 [baidu]
   └─ _initializeSourcesFromGlobal()
       ├─ 从全局管理器获取: getSources(chatId, questionId)
       ├─ 得到完整的 sources: [web_search, mcp_tool, baidu]
       └─ 使用完整的 sources 替换不完整的初始 sources  ✅
```

## 性能影响

### 内存使用

- 每个消息的 sources 存储在内存中
- 假设每个 source 100 字节，100 个消息 × 20 个 sources = 200KB
- 影响可忽略

### CPU 使用

- 去重逻辑使用 HashSet，时间复杂度 O(n)
- 每次 metadata 更新只处理增量数据
- 影响可忽略

## 与第一次修复的关系

### 第一次修复（引用累积）

- **问题**：流式传输过程中，新的 metadata 替换旧的 sources
- **解决**：在 `_ReceiveMetadata` 中使用 `_mergeSources` 累积 sources
- **效果**：流式传输过程中可以看到所有工具的引用

### 第二次修复（引用持久化）

- **问题**：消息重新加载后，累积的 sources 丢失
- **解决**：使用全局管理器持久化累积的 sources
- **效果**：消息重新加载后仍能看到所有工具的引用

### 两次修复的配合

```
第一次修复：流式过程中累积 ─┐
                             ├─ 第二次修复：持久化到全局管理器
第二次修复：从全局管理器恢复─┘
```

## 后续优化建议

1. **内存管理**：
   - 考虑清理长时间未使用的 sources（如 1 小时后）
   - 当聊天被关闭时，清理对应的 sources

2. **持久化存储**：
   - 如果需要跨应用重启保留，可考虑将 sources 持久化到本地存储
   - 使用 SharedPreferences 或 Hive

3. **后端改进**：
   - 理想的解决方案是后端累积所有 metadata
   - 但前端方案已经能完美解决问题
