## 问题 1: Provider 作用域错误 (已修复)

### 现象
点击"保存"按钮时报错：
```
Error: Could not find the correct Provider<WebSearchSettingsBloc> above this _AddWebSearchProviderDialog Widget
```

### 原因
`showDialog` 创建的对话框在新的路由中，无法访问父 widget 树中的 `WebSearchSettingsBloc`。

### 解决方案
使用 `BlocProvider.value` 传递 bloc 到对话框：

```dart
void _showAddProviderDialog(BuildContext context) {
  final bloc = context.read<WebSearchSettingsBloc>();
  showDialog(
    context: context,
    builder: (dialogContext) => BlocProvider.value(
      value: bloc,
      child: const _AddWebSearchProviderDialog(),
    ),
  );
}
```

### 修复文件
- `appflowy_flutter/lib/plugins/ai_chat/widgets/web_search_settings.dart`
  - `_showAddProviderDialog()` (2处)
  - `_showProviderConfigDialog()` (2处)
  - `_showDeleteConfirmDialog()`
  - `_showClearCacheDialog()`

## 问题 3: 异步运行时嵌套错误 (已修复)

### 现象
点击"测试所有连接"后一直显示"连接中"，应用 panic：
```
Cannot start a runtime from within a runtime
```

### 原因
在异步上下文中使用 `block_on` 导致运行时嵌套错误：

```rust
// ❌ 错误的做法
fn execute_provider_tests(&self, config: &WebSearchProviderConfigPB) -> FlowyResult<...> {
    let rt = tokio::runtime::Handle::current();
    let test_response = rt.block_on(provider.run_tests())?;  // 嵌套错误！
}
```

### 解决方案
将同步方法改为异步，使用 `await` 替代 `block_on`：

```rust
// ✅ 正确的做法
async fn execute_provider_tests(&self, config: &WebSearchProviderConfigPB) -> FlowyResult<...> {
    let test_response = provider.run_tests().await?;  // 直接 await
}
```

### 修复文件
- `rust-lib/flowy-ai/src/web_search/provider_manager.rs`
  - `test_provider()` - 改为 async
  - `execute_provider_tests()` - 改为 async，移除 block_on
  - `test_provider_testing()` - 改为 #[tokio::test]
- `rust-lib/flowy-ai/src/web_search/hub.rs`
  - `test_provider()` - 添加 .await

## 技术要点总结

### Flutter Provider 作用域
1. Dialog 在新路由中，需要显式传递 Provider
2. 使用 `BlocProvider.value` 传递现有 bloc
3. 避免在 dialog builder 中直接读取 context

### Rust 异步编程
1. 在异步上下文中使用 `await` 而不是 `block_on`
2. 保持调用链的异步一致性
3. 使用 `#[tokio::test]` 测试异步代码
4. 避免运行时嵌套

### 国际化支持
1. 关键词匹配要支持多语言
2. 同时检查中英文关键词
3. 确保用户界面反馈正确
