# 网络搜索工具识别修复说明

## 问题描述

在多路召回场景下，当 AI 调用多个网络搜索工具时（例如：`web_search`、`web_baidu_search`），最终只显示了部分搜索工具的引用，其他搜索工具的引用丢失。

### 具体表现

从日志可以看到调用了多个工具：
```
🔧 正在调用工具: web_search 完成 (2623ms)
🔧 正在调用工具: web_baidu_search 完成 (4914ms)
🔧 正在调用工具: web_search 完成 (2337ms)
```

但最终的"网络搜索引用"列表中，只包含了某些工具的引用，`web_baidu_search` 的引用没有显示。

## 根本原因

### 代码分析

在 `chat_message_service.dart` 的第148行，原始代码：

```dart
// ❌ 问题代码：只识别 web_search
if (toolName == "web_search") {
  Log.info("🔍 [WEB_SEARCH] Parsing web search result from tool_call");
  final citations = _extractCitationsFromSearchResult(result);
  metadata.addAll(citations);
}
```

**问题**：
- 代码使用 `==` 严格匹配，只识别 `web_search`
- 其他网络搜索工具（如 `web_baidu_search`）被错误地归类为 MCP 工具
- 导致这些工具的引用不会被提取和显示

```

  ├─ 匹配条件: toolName == "web_search" ✓

  └─ 结果: 引用正常显示 ✓

web_baidu_search 工具调用:
  ├─ 匹配条件: toolName == "web_search" ✗

```

```
  └─ 结果: 引用正常显示 ✓

web_baidu_search 工具调用:
  ├─ 匹配条件: toolName.startsWith("web_") && toolName.contains("search") ✓
  ├─ 提取引用: _extractCitationsFromSearchResult() ✓
  └─ 结果: 引用正常显示 ✓
```

## 解决方案

### 修改内容

文件：`appflowy_flutter/lib/plugins/ai_chat/application/chat_message_service.dart`

```dart
// ✅ 修复后的代码：使用模式匹配，支持多种网络搜索工具
if (toolName.startsWith("web_") && toolName.contains("search")) {
  Log.info("🔍 [WEB_SEARCH] Parsing $toolName result from tool_call");
  final citations = _extractCitationsFromSearchResult(result);
  metadata.addAll(citations);
  Log.info("🔍 [WEB_SEARCH] Extracted ${citations.length} citations from $toolName");
}
```

### 支持的工具

修复后支持的网络搜索工具命名模式：
- ✅ `web_search` - 通用网络搜索
- ✅ `web_baidu_search` - 百度搜索
- ✅ `web_google_search` - 谷歌搜索
- ✅ `web_bing_search` - Bing 搜索
- ✅ `web_duckduckgo_search` - DuckDuckGo 搜索
- ✅ 任何以 `web_` 开头并包含 `search` 的工具

### 匹配规则

工具必须同时满足两个条件才会被识别为网络搜索工具：
1. **前缀匹配**：`toolName.startsWith("web_")` - 以 "web_" 开头
2. **关键词匹配**：`toolName.contains("search")` - 包含 "search"

**示例**：
```dart
"web_search"           → ✓ 匹配（前缀 ✓ + 关键词 ✓）
"web_baidu_search"     → ✓ 匹配（前缀 ✓ + 关键词 ✓）
"web_google_search"    → ✓ 匹配（前缀 ✓ + 关键词 ✓）
"web_scraper"          → ✗ 不匹配（前缀 ✓ + 关键词 ✗）
"search_tool"          → ✗ 不匹配（前缀 ✗ + 关键词 ✓）
"mcp.search"           → ✗ 不匹配（前缀 ✗ + 关键词 ✓）
```

## 引用合并说明

### 现有行为

所有网络搜索工具的引用都会合并显示在**同一个"网络搜索引用"列表**中：

```
📱 网络搜索引用 (15 个)
  1. 来自 web_search 的引用 1
  2. 来自 web_search 的引用 2
  3. 来自 web_baidu_search 的引用 1
  4. 来自 web_baidu_search 的引用 2
  5. ...
```

### 优点

- ✅ **统一展示**：用户不需要在多个列表间切换
- ✅ **去重处理**：相同的 URL 不会重复显示
- ✅ **简洁界面**：避免界面混乱

### 如果需要区分来源

如果未来需要区分不同搜索引擎的引用（例如分别显示"谷歌搜索"和"百度搜索"），可以：

1. **方案1**：修改 `ChatMessageRefSource` 的 `source` 字段
   ```dart
   // 当前：统一使用 'web'
   source: 'web'
   
   // 修改为：使用具体的搜索引擎名称
   source: 'web:baidu'  // 百度搜索
   source: 'web:google' // 谷歌搜索
   ```

2. **方案2**：在 UI 层按来源分组显示
   ```dart
   // 在 ai_text_message.dart 中
   if (_hasBaiduSearchCitations(state.sources))
     UnifiedReferenceDisplay(
       references: _extractBaiduSearchSources(state.sources),
       referenceType: ReferenceType.baiduSearch,
     ),
   
   if (_hasGoogleSearchCitations(state.sources))
     UnifiedReferenceDisplay(
       references: _extractGoogleSearchSources(state.sources),
       referenceType: ReferenceType.googleSearch,
     ),
   ```

## 相关修复

该修复是多路召回系统优化的第三个修复：

1. **第一次修复**：引用累积修复
   - 问题：流式传输过程中引用被覆盖
   - 解决：使用 `_mergeSources` 累积引用

2. **第二次修复**：引用持久化修复
   - 问题：消息重新加载后引用丢失
   - 解决：使用 `SourcesManager` 全局管理器

3. **第三次修复**（本次）：网络搜索工具识别修复
   - 问题：只识别 `web_search`，其他搜索工具被错误归类
   - 解决：使用模式匹配识别所有网络搜索工具
